# 002-D — Android Cloud Mail через Media3

## Архитектура и ограничения

Android ExoPlayer 1.11.1 использует `ProgressiveMediaSource` и собственный
`DataSource`. Его JNI-мост принимает только непрозрачный идентификатор потока,
смещение и размер буфера. Адрес WebDAV, путь `/AllMusic`, почта, пароль и HTTP
заголовки остаются в C++ и не попадают в MediaItem URI, Java или QML.

Используется общий read-only Cloud Mail WebDAV клиент и его Range-устройство.
Каждый GET ограничен 64 КиБ, кэш — четырьмя страницами (256 КиБ); допустим только
HTTP 206 с согласованными Content-Range, размером, framing и ETag/If-Range.
HTTP 200 останавливает поток: полный файл не загружается. TLS остаётся строгим,
редиректы запрещены. В APK запрашивается только `INTERNET`.

Перед отправкой реквизитов C++ выполняет HTTPS HEAD к закреплённому origin `/`
без WebDAV пути, Authorization и cookies. Любой HTTP-ответ без перенаправления
подтверждает DNS, соединение и TLS; затем отдельно проверяется `/AllMusic` с
реквизитами. При отсутствии TLS backend проверка останавливается до отправки
реквизитов. На Android Qt `qopensslbackend` использует упакованные из официальных
исходников OpenSSL 3.5.9 библиотеки `libcrypto_3.so` и `libssl_3.so`. Сертификаты
проверяются обычным Qt backend, исключений и обхода проверки нет.

При ошибке экран показывает фиксированную категорию сети, числовой код Qt,
наличие/название TLS backend, версию runtime и HTTP статус, если он получен.
Диагностика не включает URL, текст Qt error, email, заголовки, сертификат или
имя файла. Для отчёта достаточно переписать эту строку без дополнений.

Список показывает MP3/FLAC и подпапки только внутри `/AllMusic`. Выбор файла не
запускает GET; сеть начинается после нажатия «Воспроизвести выбранный MP3 / FLAC».
Пароль не сохраняется и вводится только на телефоне. В CI используются только
синтетические аудиоданные и локальный mock WebDAV.

## Проверка на Huawei

1. Установите APK `AllMusic Player — Cloud Mail Media3` (package ID
   `org.metravolokos.allmusicplayer.cloud002dmedia3`). Интернет — обычное
   разрешение приложения; системного запроса на runtime-доступ ожидаться не
   должно. Разрешения на файлы, медиа, Bluetooth, микрофон или камеру не нужны.
2. На телефоне введите адрес почты и пароль внешнего приложения Cloud Mail.
   Не отправляйте пароль в чат, issue, PR или отчёт. Нажмите «Подключить» и
   дождитесь списка `/AllMusic`.
   Если появляется ошибка, запишите только безопасную диагностическую строку,
   показанную приложением. При категориях `TLS backend недоступен` или
   `TLS handshake/certificate validation` остановитесь и сообщите код Qt и
   доступные backends; повторно пароль вводить не нужно.
3. Откройте подпапку и вернитесь кнопкой «Назад». Выберите MP3, нажмите
   «Воспроизвести выбранный MP3 / FLAC» и проверьте слышимый звук, паузу,
   продолжение и перемотку.
4. Нажмите Stop, затем Play / Resume. Переключитесь на FLAC и повторите
   воспроизведение, паузу, seek и Stop/Play.
5. Во время воспроизведения отключитесь и подключитесь повторно. Экран не должен
   зависнуть, поток должен остановиться, после нового подключения можно выбрать
   другой трек. Повторите disconnect во время буферизации, если удаётся.
6. Необязательно: сверните приложение. Для этого среза ожидается остановка
   воспроизведения; фоновая служба не входит в задачу.

В отчёте укажите только результат по MP3/FLAC, управление, seek, Disconnect и
модель Android-устройства. Не указывайте email, названия и пути файлов, URL,
заголовки, ETag, пароль или системные логи. До этой ручной проверки статус
реального Cloud Mail на Huawei — **НЕ ПРОВЕРЕНО**.
