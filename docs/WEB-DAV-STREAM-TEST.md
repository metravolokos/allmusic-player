# Потоковая проверка на Windows 11 — задача 001-E

Инструкция предназначена для портативного архива `AllMusicPlayer-Windows-x64`
из успешного Desktop CI PR. Нужны Windows 11, наушники или колонки и комплектный
архив. Устанавливать Python, Qt SDK, FFmpeg или IDE не требуется. Все файлы —
синтетические тоны CC0; сервер доступен только через `127.0.0.1`, путь
`/AllMusic`. Настоящее облако, учётные данные и личная музыка не используются.

## Проверка слышимого потокового звука

1. Скачайте из PR артефакт `AllMusicPlayer-Windows-x64`. Распакуйте архив GitHub,
   затем ZIP приложения в обычную локальную папку. Не запускайте EXE из ZIP.
2. В Windows выберите наушники/колонки и установите небольшую громкость.
3. Дважды щёлкните `start-webdav-demo.bat`. Откроются окно локального mock и
   приложение. Оставьте оба окна открытыми; сервер указывает `127.0.0.1:8765`.
4. В приложении нажмите «Найти файлы». По очереди выберите:

   - `tone-stream-mp3.mp3` — MP3;
   - `tone-stream-flac.flac` — FLAC;
   - `tone-stream-aac-adts.aac` — AAC-LC ADTS;
   - `tone-stream-aac-m4a.m4a` — AAC-LC в M4A;
   - `tone-stream-alac-m4a.m4a` — ALAC в M4A.

5. Для каждого файла подтвердите **на слух**, что слышен ровный тихий тон,
   а позиция и длительность отображаются. На этот субъективный тест не влияет
   успешный статус декодера или движение ползунка.
6. Во время каждого трека проверьте паузу и продолжение, перемотку сначала
   примерно на 5-ю секунду, затем на незагруженную область около 25-й секунды,
   повторную перемотку в другое место и Stop. После Stop оставьте выбранным тот
   же файл и нажмите «Воспроизвести»: тон должен начаться снова, а окно mock
   показать новый GET с Range. Ещё раз проверьте паузу/продолжение, затем
   переключитесь на следующий файл. Счётчик показывает полученные байты тела
   ответов 206; окно mock печатает HTTP-метод, путь и Range.
7. Проверьте локальный Stop: нажмите «Выбрать аудиофайл…», откройте
   `audio-fixtures/tone-mp3.mp3`, прослушайте тон, выполните паузу/продолжение,
   нажмите Stop и снова «Воспроизвести». Локальный тон должен запуститься снова;
   этот сценарий не должен добавлять HTTP-запросы в окно mock.
8. Для проверки отказа при сервере без Range закройте обычный mock и запустите
   `start-webdav-no-range.bat`. Выберите файл: клиент должен сообщить про HTTP
   200 вместо 206 и прекратить поток, не скачивая весь файл автоматически.
9. По окончании закройте приложение и оба окна mock.

## Автоматическая проверка PCM

Из распакованной папки откройте PowerShell и выполните:

```powershell
$env:QT_MEDIA_BACKEND = 'ffmpeg'
$env:QT_FFMPEG_PROTOCOL_WHITELIST = 'file'
$env:ALLMUSIC_FIXTURES = "$PWD/audio-fixtures"
./streaming-tests.exe -o "streaming-results.txt,txt"
$LASTEXITCODE
```

Ожидается код 0. Вывод содержит измеренные времена первого PCM и перемотки,
переданные Range-байты, кэш адаптера и оценку пикового RSS процесса. RSS —
пиковое потребление всего тестового процесса, не только Qt/FFmpeg и не только
адаптера. Тест отключает звуковой выход: он **не проверяет слышимый звук**.
Отчёт о сетевых прерываниях также не доказывает отсутствие щелчков или пауз
на физических наушниках. Для этого отдельно выполните ручные шаги выше.

Если звук не слышен, сначала проверьте микшер Windows, устройство по умолчанию
и его громкость. Запишите версию Windows (`winver`), имя файла, слышимый результат,
управление и номер CI запуска. Для отчёта используйте только комплектные
синтетические тоны; не отправляйте личные аудиофайлы и сетевые реквизиты.

Сервер должен оставаться только loopback. Не меняйте адрес и не подключайте
реальный WebDAV: этот архив и клиент предназначены для безопасной локальной
проверки. Запишите результат прослушивания отдельно для пяти форматов, а также
что произошло при сетевом Stop/restart и локальном Stop/restart. Автотесты
подтверждают отмену HTTP-ответа и поступление PCM; только ручная проверка может
подтвердить, что звук был слышен на выбранном устройстве.
