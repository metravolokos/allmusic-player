# Ручная демонстрация потокового WebDAV (001-B2)

Архив предназначен для теста на Windows 11. Python, Qt и IDE не нужны.
Внешний тестовый сервер принимает соединения только на `127.0.0.1`, читает
комплектные синтетические сигналы и показывает их в `/AllMusic`. Запросы записи
и удаления сервер отклоняет. Реальное облако и личные файлы не используются.

1. Распакуйте архив `AllMusicPlayer-Windows-x64.zip` в папку пользователя.
2. Дважды щёлкните `start-webdav-demo.bat`. Он запустит loopback сервер и
   приложение; установщик, Python, Qt и IDE не нужны. Окно сервера покажет порт
   `8765` и останется открытым до конца проверки.
3. Если предпочитаете запускать сервер вручную, используйте параметры:

   ```text
   webdav-mock.exe --root audio-fixtures --port 8765
   ```

   Окно сообщит, что сервер доступен только на `127.0.0.1:8765`. Не закрывайте
   его до конца проверки, затем вручную запустите `allmusic-player.exe`.
4. В блоке «Локальный тестовый WebDAV» нажмите «Найти файлы» и выберите
   `tone-stream-flac.flac`. Выбор сразу начинает воспроизведение.
5. Проверьте отдельно **слышимый звук** и управление pause/resume/stop/seek.
   Счётчик показывает payload-байты успешно проверенных ответов 206, без HTTP
   заголовков.
6. Для seek нажмите ползунок около 25-й секунды ещё не загруженного трека. В
   консольном окне mock-сервера должны появиться отдельные GET `Range`-запросы.
7. Чтобы проверить fallback, закройте обычное окно mock-сервера. Дважды
   щёлкните `start-webdav-no-range.bat`; он запустит сервер с ответом 200 и
   приложение. Клиент должен явно показать HTTP 200 и остановить поток.

   Эквивалентная ручная команда:

   ```text
   webdav-mock.exe --root audio-fixtures --port 8765 --ignore-range
   ```

   Эта команда используется, если запускать тест вручную.

Автоматический тест PCM не подтверждает вывод на аудиоустройство. Не указывайте
в поле порт сервисы, отличные от запущенного локального mock: клиент жёстко
привязан к `127.0.0.1`, `/AllMusic` и проверяет маркер `001-B2-loopback` в
каждом HTTP-ответе.
