# Проверка 001-C на Huawei: инструкция владельцу

Это тестовый экран, а не музыкальный плеер. Совместимость Huawei nova 15 Pro /
EMUI 15 пока **НЕ ПРОВЕРЕНА**. Первый пакет экспериментальный `arm64-v8a`:
модель телефона и EMUI не подтверждают ABI, Android API или поддержку APK.
Qt, Android Studio и учётная запись Google для запуска не нужны.

## 1. Что узнать о телефоне

В «Настройки → О телефоне» запишите название ОС, её версию и номер сборки.
Не отправляйте IMEI, серийный номер, телефон, адрес аккаунта или полный снимок
раздела с личными идентификаторами. Установка APK должна поддерживаться самой ОС.
Если это не Android-совместимая среда, остановитесь: пакет HAP этой задачей не создаётся.

Точный API/ABI можно прочитать без программирования на своём компьютере:

1. Скачайте [официальные Platform Tools для Windows](https://developer.android.com/tools/releases/platform-tools).
   Распакуйте ZIP целиком. Android Studio и полный SDK не требуются.
2. В настройках телефона включите режим разработчика (обычно 7 нажатий на
   «Номер сборки», затем собственный PIN) и USB-отладку. В EMUI названия могут отличаться.
3. Подключите кабель передачи данных. Разрешите отладку только своему компьютеру.
4. Откройте распакованную папку `platform-tools` в Проводнике, в адресной строке
   введите `powershell` и нажмите Enter. Скопируйте команды по одной:

   ```powershell
   .\adb.exe shell getprop ro.build.version.release
   .\adb.exe shell getprop ro.build.version.sdk
   .\adb.exe shell getprop ro.product.cpu.abilist
   ```

5. Первая строка — версия Android, вторая — API, третья — поддерживаемые ABI.
   Для первого APK нужен `arm64-v8a` в третьем ответе; официальный диапазон
   Qt 6.12 — API 28–36. API за пределами диапазона требует отдельной оценки.
6. Если отображается `unauthorized`, проверьте запрос на телефоне. Если устройство
   не найдено — проверьте кабель/USB-режим, не устанавливайте случайные драйверы.
   При недоступном ADB значения остаются НЕ ПРОВЕРЕНЫ. Можно отдельно согласовать
   доверенную утилиту, показывающую именно API и ABI; угадывать их не нужно.
7. Отключите USB-отладку и отзовите разрешение компьютера после проверки.

Команды только читают свойства; root и разблокировка загрузчика не нужны.
Наличие EMUI само по себе не доказывает поддержку APK. Ничего не отключайте
в системной защите, если ОС не предлагает штатную установку.

## 2. Скачать правильную сборку

1. Войдите в GitHub под аккаунтом с доступом к частному репозиторию.
2. Откройте PR задачи 001-C → Checks → **Android 001-C / apk** → Details.
   Либо откройте вкладку Actions репозитория и выберите **Android 001-C**.
3. Выберите успешный запуск для нужного коммита. Ссылка и маркировка проверенной
   сборки указываются в PR/отчёте. У PR сборка проверяет merge commit с main,
   поэтому его SHA может отличаться от SHA последнего коммита ветки.
4. Внизу страницы в **Artifacts** скачайте ZIP с именем:
   `AllMusicPlayer-001C-Android-arm64-v8a-debug-<SHA>-<runID>-<attempt>`.
   Артефакт `Android-001C-diagnostics-...` предназначен для диагностики, APK в нём нет.
5. Артефакты хранятся 14 дней. Если истекли — сообщите об этом; нужна новая
   ручная сборка, а не APK со стороннего сайта. После объединения workflow будет
   доступна кнопка **Run workflow** для будущих ручных запусков.
6. Распакуйте ZIP: на телефоне через «Файлы», на компьютере — «Извлечь всё».
   Внутри один APK, инструкция, BUILD-INFO.json, SHA256SUMS.txt, лицензии и аудит.
   Сверьте маркировку с согласованным запуском. Если скачали на компьютере,
   скопируйте APK на телефон кабелем в «Загрузки».

Необязательно: на Windows в папке пакета откройте PowerShell и выполните
`Get-FileHash .\AllMusicPlayer-*.apk -Algorithm SHA256`. Сравните результат
с записью APK в SHA256SUMS.txt: регистр букв не важен. Сумма подтверждает
целостность файла; источник подтверждается выбранным запуском GitHub.

## 3. Установить

1. Откройте APK в «Файлах». Если появляется запрос установки из этого источника,
   разрешите её только этому приложению (или браузеру, если открыли APK из него).
   Названия пунктов EMUI могут отличаться: «Установка неизвестных приложений»,
   «Разрешить из этого источника». Глобально отключать защиту не нужно.
2. Проверьте название: **AllMusic Player — тест 001-C**. Установите.
3. Если система запрещает установку, сохраните точный текст ошибки и остановитесь.
   Не обходите корпоративную политику, не отключайте проверку приложений целиком.
4. Разрешение установки из выбранного источника после установки верните в исходное состояние.

Важное ограничение: каждая CI-сборка может иметь новую отладочную подпись.
Если новая копия не обновляет старую, сначала запишите ошибку, затем удалите
**только AllMusic Player — тест 001-C** через настройки приложений и установите
новую. Package ID: `org.metravolokos.allmusicplayer.spike001c`. Удаление стирает
данные этой тестовой копии. Она не содержит музыку/аккаунты. Нельзя применять
этот способ к будущей полноценной версии без сохранения её данных.

## 4. Проверить экран

1. Нажмите «Открыть»: видна надпись «AllMusic Player — проект запущен» и метка
   `001-C-...`. Запишите её. Чёрный экран или мгновенное закрытие — не успех.
2. Подождите 30 секунд: нет зависания, аварийного закрытия или запросов разрешений.
3. При включённом автоповороте поверните телефон в обе ориентации. Текст читается,
   не обрезается и не скрывается за вырезом/системными панелями.
4. Нажмите «Домой», вернитесь через последние приложения. Заблокируйте экран,
   разблокируйте и вернитесь. Экран снова отображается. Фоновую службу здесь не проверяют.
5. Смахните приложение из последних и запустите с иконки повторно. Проверьте
   системную кнопку/жест «Назад» и новый запуск.
6. Включите авиарежим и повторите запуск. Верните сетевые настройки после проверки.
   Запишите, установлены ли Google Play Services, если это известно. Не удаляйте
   и не отключайте GMS ради теста: при их наличии запуск сам по себе не доказывает
   независимость; дополнительно используется статический аудит пакета.

Этот APK не должен запрашивать сеть, файлы, медиа, микрофон, уведомления или аккаунты.
Если такой запрос появился, откажитесь и сообщите. Приёмка только после вашего отчёта.

## 5. Если возникла ошибка

Сообщите: метку сборки/ссылку на запуск, название ОС, API/ABI (если определены),
этап ошибки (скачивание/распаковка/установка/запуск/поворот/возврат), точный текст,
ожидаемое и фактическое поведение. Снимок обрежьте до ошибки без уведомлений и аккаунтов.

Если текст установщика слишком общий, можно получить код на своём компьютере:
подключите телефон по инструкции выше, скопируйте APK в папку platform-tools,
введите ` .\adb.exe install ` (без начального пробела), затем перетащите APK
в окно PowerShell, чтобы подставился его полный путь, и нажмите Enter.
Это устанавливает выбранный пакет по вашему действию. Передайте только строку
`Failure [...]` или `Success`. Не добавляйте `-d`/обходы проверок.

При сбое запуска понадобится короткий журнал именно приложения. Через
`.\adb.exe shell pidof org.metravolokos.allmusicplayer.spike001c` можно узнать PID,
а `.\adb.exe logcat --pid=ЧИСЛО -d -t 200` прочитать последние сообщения живого
процесса (замените ЧИСЛО ответом). Если процесс уже завершился, эта команда
не поможет: сообщите об этом для отдельной инструкции. Не отправляйте полный
logcat/bugreport, не используйте команды очистки общесистемного журнала.
Перед передачей проверьте журнал на личные сведения; после выключите USB-отладку.

Типичные направления диагностики: `NO_MATCHING_ABIS` — ABI, `OLDER_SDK` — API,
`UPDATE_INCOMPATIBLE` — подпись, `UnsatisfiedLinkError` — native runtime.
Это подсказки, причина определяется по фактической ошибке.
