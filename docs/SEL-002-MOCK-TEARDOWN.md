# SEL-002 — изоляция Windows mock WebDAV streaming-тестов (Issue #35)

Исходная ветка: `main` `9c5d144c58319fece454da372744583ac10e9523`. PR #34 оставлен без изменений.

## Наблюдение
При [Windows CI PR #34 run 41238299167](https://github.com/metravolokos/allmusic-player/actions/runs/41238299167) основные 6/6 CTest прошли, но второй запуск `streaming-tests.exe` из упакованного каталога завершился `15 passed / 21 failed`. Первый отказ: `range416FailsClosed` обнаружил `Authorization`, допустимый только в предыдущих Mail-фикстурах. Следом `cleanup()` вышел на первом же `QVERIFY` и оставил сервер открытым. Остальные тесты упали на `QTcpServer::listen() called when already listening`.

Появление авторизованного запроса за границей тестов — **не доказанный дефект production клиента**. Сохраняем fail-closed проверку заголовка и все ограничения.

## Узкое исправление
- `MockWebDav::stop()` закрывает слушающий сокет **и принятые TCP-соединения** (обычный `QTcpServer::close()` не делает второе).
- `StreamingTests::cleanup()` использует RAII teardown, который срабатывает даже при первом проваленном `QVERIFY/QCOMPARE`; очередь запросов не переносится в следующий тест.
- Проверка завершённых ответов выполняется до аудита полного списка запросов, чтобы поздние события успели попасть в проверку.
- Новый тест с намеренно недописанным HTTP-запросом (только фиктивные данные) проверяет уничтожение открытого соединения и отсутствие принятого GET.

## Не изменено
Рабочие WebDAV client, Mail Range, Android Media3/JNI, Desktop playback, Qt/FFmpeg, авторизация, HTTP 206, UI, CI workflow и кеширование. Любое повторное появление `Authorization` на non-Mail-файлах остаётся **ошибкой**, а не игнорируется.

## Критерии приёмки
Windows CTest и Windows packaged streaming, Linux CTest. Повторный Windows packaged failure необходимо исследовать по первому FAIL, не устранять исключением из аудита. Android не должен требовать тяжёлого полного прогона: production и платформенная конфигурация не менялись. Локальной Windows/Qt среды для полного воспроизведения нет — статус отражается только по фактическим GitHub CI.
