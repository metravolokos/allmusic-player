# 001-B1 — отчёт локального аудиопрототипа

## Реализация и границы

Изолированный исследовательский LocalPlayback использует QMediaPlayer,
QAudioOutput и FFmpeg backend. QML Desktop предоставляет выбор файла,
play/pause/stop, seek, volume, длительность/позицию и ошибки. Начальная громкость
25%. Нет очереди, сети, WebDAV-подключения, кэша, БД, gapless и Android audio.
Предварительный IPlaybackEngine не превращён в окончательный контракт.

Допускаются локальные файлы с заголовками MP3/FLAC/ADTS/ISO BMFF. Это первичный
фильтр содержимого, а не полная проверка кодека. Реальный декодер открывает
контейнер; расширение не определяет формат. URL/UNC/папки/текстовые плейлисты
отклоняются; FFmpeg protocol whitelist ограничен file. Это не security sandbox
для произвольных недоверенных медиа: вложенные локальные ссылки контейнера
специально не исследованы. Облачные источники не реализованы.

## Фикстуры и тесты

`scripts/generate-audio-fixtures.py` создаёт 8-секундные синтетические 440 Гц
стереосигналы с плавным входом/выходом: MP3 128 kbps, FLAC 16 bit,
AAC-LC 128 kbps ADTS и M4A, ALAC 24 bit M4A. Сигнал/manifest — CC0-1.0;
нет музыки пользователя и чужих фонограмм. Генерация на Ubuntu передаётся
одним артефактом обеим ОС. Manifest содержит SHA256, команды, версии и ffprobe.
Побитовая идентичность между разными версиями FFmpeg не обещается.

Qt-тест получает реальные PCM-буферы через QAudioBufferOutput, требует ненулевой
амплитуды и числа кадров, проверяет pause/resume, seek, stop/restart/EOF,
volume API, испорченный файл/восстановление и FLAC с ложным расширением MP3.
Звуковой выход теста отключён: вывод на колонки отдельно по AUDIO-TEST.md.
Нативная Windows-упаковка повторяет PCM-тест с очищенным PATH.

## Фактически исполнено в исходной Linux-среде

Debian 13 x64, FFmpeg 7.1.5 (системный, GPL-сборка только как инструмент).

- `python3 scripts/generate-audio-fixtures.py build/audio-fixtures` — ПРОЙДЕНО.
- Та же команда с `--verify-only` — ПРОЙДЕНО: пять кодеков/контейнеров,
  AAC LC, ALAC 24 bit, 44100 Hz/stereo, длительность и SHA256.
- `python3 -m unittest discover -s tests/android -v` — ПРОЙДЕНО, 4 теста.
- `python3 scripts/check_repository.py`, `git diff --check` — ПРОЙДЕНО.

Qt 6.12.0/CMake отсутствуют локально. Сетевой прокси shell недоступен;
актуальные исходники получены GitHub-коннектором с main `6bc62c1`.
Не подменяли Qt другой версией. Сборка/Qt PCM требуют отдельного CI результата.

## CI / устройства

Результаты CI будут внесены после исполнения. До этого сборка Windows/Linux,
Qt-декодирование, состав архива и APK-регрессия — НЕ ПРОВЕРЕНО для этой ветки.
Физический звук Windows 10/11, пользовательского Linux — НЕ ПРОВЕРЕНО.
Успех сборки, получение PCM, отправка устройству и слышимый звук различаются.

## Исследовательский вывод и 001-B2

QMediaPlayer пока остаётся кандидатом (D-008 / D-009 — ПРОВЕРИТЬ).
Перед 001-B2 нужны приёмка этого среза и отдельное разрешение, результаты
ручного звука/seek Windows 10/11 и Linux, согласованная область B2 (например,
управляемый локальный источник после mock-загрузки), политика полного файла
или Range/fallback, ограничения контейнеров и наблюдаемые критерии буферизации.
Сетевой источник, авторизация, кэш и смена архитектурного контракта потребуют
отдельного согласования. Android/gapless/выбор движка не доказаны этим срезом.

Рекомендация до проверки CI и ручного звука: не принимать как завершённый
работающий аудиоэтап. После отчёта остановиться до решения владельца.

## Первый CI (промежуточный код 55294e6)

[Desktop run 40925834771](https://github.com/metravolokos/allmusic-player/actions/runs/40925834771):
Ubuntu 24.04 / Qt 6.12.0 / FFmpeg 9.0.1 LGPL 2.1-or-later — сборка и 3/3 CTest
ПРОЙДЕНЫ. Playback: 9 passed / 0 failed; WebDAV: 86 passed / 0 failed.
Пять файлов дали ненулевой PCM, peak 0.042–0.053; pause/seek/stop/restart/EOF
пройдены. Звукового сервера CI нет (PulseAudio connect failed): физический
звук этим прогоном не проверялся. Нет необязательных VAAPI/PipeWire библиотек;
аудиодекодирование прошло без них. В журнале закрытия окна были QML обращения
к уже уничтоженному адаптеру; порядок lifetime исправлен для следующего прогона.
Окончательные результаты после исправлений фиксируются отдельно.

Первый Windows CI также собрал Qt-приложение и прошёл 3/3 CTest.
Упаковка остановилась на неправильно переданном PowerShell пути журнала;
исправлено кавычками вокруг всего аргумента `path,txt`.
Android APK собрался, но строгий аудитор отклонил дополнительные Desktop QML
модули: Qt рекурсивно сканировал SOURCE_DIR корня репозитория. Проверка исходников
Qt показала, что androiddeployqt добавляет SOURCE_DIR даже при узком
QT_QML_ROOT_PATH. Поэтому определение app target перенесено в src/app/CMakeLists:
теперь SOURCE_DIR ограничен src/app, QML задаётся явно для каждой платформы.
Публичные флаги отключения сканирования не используются; строгий аудит сохранён.
Путь промежуточной Android-упаковки изменён в workflow/package script;
Desktop EXE остаётся в прежней папке. Повторный CI обязателен.
