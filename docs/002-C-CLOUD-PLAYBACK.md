# 002-C — потоковое воспроизведение Cloud Mail

## Область задачи

Issue #22 добавляет Desktop вертикальный срез: пользователь подключается,
просматривает `/AllMusic`, выбирает MP3 или FLAC и явно запускает потоковое
воспроизведение. Android streaming, библиотечный индекс, плейлисты, offline
копии и gapless в эту задачу не входят.

Codex и CI используют только синтетические аудиофайлы и loopback mock. Нельзя
передавать реальные реквизиты, имена файлов, raw HTTP-заголовки или пользовательское
аудио в Issue, PR, лог или отчёт. Реальную проверку запускает владелец локально.

## Реализация и ограничения

- Desktop использует `QMediaPlayer::setSourceDevice()` и отдельный
  `MailWebDavRangeDevice`. Сеть и временная авторизованная сессия живут в worker
  потоке; QML не получает пароль, `Authorization`, URL источника или заголовки.
- Каждый GET запрашивает не больше 64 КиБ. В памяти хранится до четырёх страниц
  (256 КиБ). Одновременно работает не больше одного Range запроса на источник.
- Источник разрешает только закреплённый HTTPS `webdav.cloud.mail.ru:443` и
  файлы из `/AllMusic`. Записи, редиректы, cookies и ослабление TLS не включены.
- Для каждого сегмента проверяются HTTP 206, точное начало и конец,
  `Content-Range` с числовым общим размером, совпадение размера с PROPFIND,
  framing, identity encoding, фактическая длина тела и согласованность `If-Range`.
  Разрешены RFC форма `bytes first-last/total` и узкая проверенная на Cloud Mail
  форма `bytes=first-last/total`. HTTP 200 немедленно отклоняется; полная загрузка
  не запускается.
- Сильный ETag передаётся через `If-Range`. Если сильного ETag нет, диапазон,
  общий размер и тело всё равно проверяются, но сервер не предоставляет сильной
  гарантии, что несколько GET относятся к одной неизменной версии. ETag не является
  криптографическим хэшем.
- После одного HTTP 429 допускается максимум один повтор того же диапазона, если
  числовой `Retry-After` не превышает 5 секунд. Другие ошибки завершают источник
  понятным обезличенным сообщением.
- Seek обновляет целевую позицию и поколение, отменяет старый GET и отбрасывает
  поздний ответ. `QIODevice` открыт без второго уровня буфера; поток чтения
  применяет отложенный seek, чтобы не менять внутренний cursor Qt одновременно
  с чтением. Stop, Disconnect, смена источника и закрытие окна отменяют запрос и
  очищают временные реквизиты. После Stop повторный Play создаёт новый источник.
- Известные временные буферы credentials зануляются при очистке. Абсолютное
  стирание копий из памяти Qt, TLS и ОС не гарантируется; пароль не сохраняется
  на диск и не выводится в логи.
- Список показывает непосредственные элементы текущей папки. Открытие подпапок
  остаётся внутри `/AllMusic`; одно лишь выделение строки не вызывает GET.
  Кнопки воспроизведения доступны только для MP3/FLAC с известным положительным
  размером.

## Автоматические проверки

Добавленные loopback-сценарии покрывают Basic challenge и последующие Range
запросы, стандартный и Mail `Content-Range`, чтение смещённого диапазона,
слабый/отсутствующий ETag, один повтор 429, отказ при HTTP 200, seek во время
задержанного GET с переходом на новый диапазон, отмену, отключение и повторный
запуск, MP3/FLAC декодирование в PCM. Сохраняются существующие Desktop
streaming/WebDAV и Android проверки.

Desktop CI и Android CI прошли на кодовом коммите
`18ac040cb0e53dbb221e7d1d2b7c98e6951cf149`; Windows ZIP собран как Actions artifact.
Это подтверждает mock и сборку, но не работу с реальным Cloud Mail или слышимость
на Windows. Ручная приёмка владельца остаётся обязательной.

## Ручная проверка владельца на Windows 11

Проверять только локальную тестовую сборку этого PR. Вводить временные данные
непосредственно в приложение; не копировать их в чат или GitHub.

1. Подключиться через пароль внешнего приложения Mail и открыть `/AllMusic`.
2. Открыть папку с MP3, запустить воспроизведение и убедиться, что звук слышен.
3. Проверить Pause/Resume, Seek, Stop, затем повторный Play того же файла.
4. Повторить основные действия с FLAC.
5. Начать воспроизведение и выполнить Disconnect во время сетевой загрузки.
   Интерфейс не должен зависнуть; воспроизведение должно остановиться.
6. Проверить, что переходы состояния не запускают полный download и что ошибка
   HTTP 200 вместо 206 показывается без продолжения полной загрузки.
7. В отчёт вернуть только результаты сценариев и типы форматов. Не прикладывать
   имена/пути файлов, email, URL, заголовки, ETag, пароль или аудиофайлы.

Приёмка 002-C остаётся за владельцем. Успешный CI подтверждает только mock и
сборку; он не доказывает работу реального Cloud Mail или слышимость на Windows.
