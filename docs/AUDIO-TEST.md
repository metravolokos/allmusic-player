# Проверка звука 001-B1 — Windows Desktop (11/10)

**Основная система ручной приёмки — Windows 11.** Повторять тот же набор на
Windows 10 для каждого этапа необязательно (D-026); это дополнительный тест
совместимости по необходимости. В протоколе указывайте реально использованную ОС:
Windows 11 не считается фактически проверенной Windows 10.
CI Windows Server не является ручной проверкой пользовательской системы.
Архив тестовый и без цифровой подписи. Qt, Python, FFmpeg и IDE устанавливать не нужно.

1. В PR откройте успешный Desktop workflow → Artifacts → AllMusicPlayer-Windows-x64.
   Распакуйте внешний ZIP GitHub, затем ZIP приложения целиком в локальную папку.
   Не запускайте EXE из ZIP и не переносите только EXE отдельно от DLL.
2. Сохраните номер запуска и версию Windows (`winver`). Подключите наушники или
   колонки, выберите устройство вывода в Windows. Начните с небольшой громкости.
3. Запустите `allmusic-player.exe`. Нажмите «Выбрать аудиофайл…», откройте
   `audio-fixtures/tone-mp3.mp3`. Затем «Воспроизвести»: должен быть слышен
   тихий ровный тон 440 Гц в течение примерно 8 секунд. Время должно двигаться.
4. Повторите для `tone-flac.flac`, `tone-aac-adts.aac`, `tone-aac-m4a.m4a`,
   `tone-alac-m4a.m4a`. AAC и ALAC имеют одинаковое расширение M4A, разные кодеки.
   Их реальное содержимое зафиксировано ffprobe в `audio-fixtures/manifest.json`.
5. Для каждого файла проверьте паузу (тишина и время стоят), продолжение,
   перемотку к 5-й секунде, стоп (тишина, позиция 0), повторный старт и конец.
   Проверьте громкость 0% (тишина), 25%, 50%; не начинайте с максимума.
6. Откройте следующий файл во время воспроизведения. Старый звук должен остановиться.
   Отмените диалог: выбранный файл должен сохраниться. Измените размер окна.
7. Выберите текстовый файл через «Все файлы»: должна появиться понятная ошибка.
   После ошибки снова откройте исправный тон: плеер должен восстановиться.
8. Закройте приложение, отключите интернет, откройте снова и проверьте тон.
   Учётные данные и личная музыка не нужны; сетевые папки не поддерживаются.

Автоматическая проверка декодирования упакованной копии: откройте PowerShell
в распакованной папке и выполните:

```powershell
$env:QT_MEDIA_BACKEND = 'ffmpeg'
$env:QT_FFMPEG_PROTOCOL_WHITELIST = 'file'
$env:ALLMUSIC_FIXTURES = "$PWD/audio-fixtures"
./playback-tests.exe -o "playback-results.txt,txt"
$LASTEXITCODE
```

Ожидается код 0. Этот тест намеренно отключает звуковое устройство, проверяет
ненулевой PCM, управление и EOF. Он **не доказывает слышимый звук**. Само движение
ползунка также не доказывает звук. Полный прогон занимает около минуты.
Не отправляйте логи личных файлов: используйте только комплектные тоны.

Запишите для каждой ОС и каждого файла: звук слышен / нет; pause/resume,
seek/stop/volume, ошибки, тип устройства и вывод автоматического теста.
Если не слышно, проверьте микшер Windows, устройство по умолчанию и громкость.
Если не хватает DLL, сохраните точный текст сообщения; не скачивайте DLL со
случайных сайтов. Передайте результат владельцу PR; приёмка отдельно.

Linux: установите Qt 6.12.0 с Multimedia/Quick Controls, соберите по BUILD.md,
сгенерируйте фикстуры и запустите приложение в обычной графической сессии.
Повторите пункты 3–8, укажите дистрибутив, Wayland/X11 и PulseAudio/PipeWire/ALSA.
Headless PCM-тест не проверяет пользовательский Linux или физический звук.
