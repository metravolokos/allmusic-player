# 001-A: исследование WebDAV

## Понятный вывод

Подготовлен безопасный локальный стенд. Он проверяет, как клиент читает список
файлов и диапазоны байтов, реагирует на ошибки и не выходит за /AllMusic.
Результаты автоматического выполнения будут внесены после CI.
Возможности настоящего Cloud.Mail.ru, звук и Android этим стендом не подтверждены.

## Устройство и пределы

Клиент WebDavProbe работает асинхронно через Qt Network и доступен только на
127.0.0.1 с заданным портом. Методы — PROPFIND Depth:1 и GET Range. Произвольных
HTTP-методов и реквизитов нет. Сетевой менеджер приватный. Редиректы запрещены.
TLS-проверка в клиенте не отключается. Имитация полностью в памяти, не читает
файлы с диска и не передаёт запросы внешним серверам; слушает только IPv4 loopback.
Режим HTTPS с тестовым сертификатом применяется в автоматическом отрицательном тесте.
Файлы localhost.crt и localhost.testkey — публичные самоподписанные тестовые данные,
созданные для стенда, без доступа к чему-либо; никогда не устанавливать их в доверенные.

Политика путей намеренно строгая: неоднозначные пути, двойное кодирование,
повторные разделители и сегменты . / .. отклоняются. Обычные кириллица, пробел,
кодированные # и % поддерживаются; имя с буквальным текстом вроде %2f отвергается.
Это ограничение совместимости, а не обещание поддержки любого имени Mail.

Одна операция одновременно; запрос второй возвращает false. Общий дедлайн 3 с,
максимум 3 попытки для 408/429/5xx, задержки с jitter. Retry-After 0–1 с учитывается;
более длинное/HTTP-date значение возвращает ошибку без преждевременного повтора.
Обрывы сети не возобновляются автоматически. Отмена прекращает запрос и таймер повтора.
PROPFIND ограничен 4 МиБ и 10 000 записей, диапазон — 1 МиБ. Это пределы прототипа,
не окончательные настройки приложения. Тело целиком хранится в памяти; кэша пока нет.

Для диапазона проверяются 206, Content-Range, размер тела и ETag при If-Range.
Ответ 200 не используется как фрагмент и прекращается без полной загрузки.
Для безопасного продолжения нужен сильный ETag; слабый валидатор не отправляется
в If-Range. Без ETag можно исследовать отдельный диапазон, но нельзя считать
безопасной склейку разных ответов. Итогового механизма склейки здесь нет.

## Как повторить

Разработчик с утверждённой Qt 6.12.0:

```sh
cmake --preset desktop-release
cmake --build --preset desktop-release --parallel 2
ctest --test-dir build/desktop-release -R webdav-safety --output-on-failure
```

Полная регрессия — `ctest --preset desktop-release` (Linux: через xvfb-run).
Стенд можно запустить отдельно: `webdav-mock`, затем `webdav-probe НОМЕР_ПОРТА`,
напечатанный сервером. Ожидается error=0, http=207, entries=1; остановка Ctrl+C.
Отдельный сервер демонстрирует PROPFIND; сложные сценарии настраиваются внутри тестов.

Владельцу на Windows 10:

1. В успешной проверке PR открыть Artifacts → WebDav001A-Windows-x64.
2. Распаковать оба ZIP, если GitHub добавил внешнюю оболочку; оставить все файлы вместе.
3. Открыть PowerShell в распакованной папке.
4. Выполнить `./webdav-tests.exe -o result.txt,txt`.
5. Выполнить `$LASTEXITCODE` — ожидается 0. В result.txt ожидается 0 failed.
6. Сообщить номер сборки Windows из winver, ссылку на CI и итоговую строку отчёта.

Qt/IDE устанавливать не нужно. Пароль, интернет и музыка для теста не нужны.
В тесте forbiddenMethodsOnServer намеренно отправляются методы записи к ВТОРОЙ
локальной имитации и проверяется 405. Это не запросы исследовательского клиента:
его запросы отдельно проверяются после каждого сценария — только GET/PROPFIND.

## Результаты и ограничения приёмки

На момент подготовки: сборка/исполнение новых C++ тестов ожидают CI; локально
нет Qt/CMake, сетевой прокси среды недоступен. Результаты будут обновлены.
На Windows 10, Windows 11 и пользовательском Linux новые тесты НЕ ПРОВЕРЕНЫ.
Реальный Mail НЕ ПРОВЕРЕН: любые обращения только с отдельного согласия владельца,
только чтение, без личных данных в CI. QMediaPlayer не выбран аудиодвижком.
После 001-A остановиться; 001-C, 001-B, 001-D требуют новых разрешений.
