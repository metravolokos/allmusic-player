# Техническое задание — AllMusic Player

**Редакция:** 0.1 / 29.10.2026. **Статус:** документация v0.1 утверждена владельцем; уточнения задачи 000 от 29.10.2026. Под «обязательно» ниже понимается целевое требование к версии 1.0, а не уже реализованная функция.

## 1. Цель и область применения

Персональное приложение для одного пользователя, предназначенное для прослушивания музыкальной коллекции в облаке Mail (`/AllMusic` через WebDAV) на Windows, Linux и Android. Одна кодовая база; общая функциональность; отдельные представления для Desktop и Android. Приложение не является публичным облачным музыкальным сервисом, не предполагает многопользовательскую систему и не требует собственного сервера.

### 1.1 Подтверждённые исходные требования

- Аудиоформаты: MP3, FLAC, AAC, ALAC (проверить реальные контейнеры и варианты кодирования: `.mp3`, `.flac`, `.m4a`, `.mp4`, `.aac` и др.).
- Этот исходный перечень v1.0 не расширяет критерии задачи #26: для Android Media3 spike обязательны только MP3/FLAC, WAV нужен лишь для локальной регрессии; ALAC не входит в требования и приёмку этого spike.
- Единственный источник первоначально: WebDAV Облака Mail; рабочая корневая папка — `/AllMusic`.
- ОС: Windows, Linux, Android; Desktop-интерфейс единый, Android-интерфейс отдельный; общее ядро.
- Быстрый каталог, умные кэши аудио и обложек, устойчивое воспроизведение, офлайн.
- Первоначально только операции чтения с облака; загрузка, запись, изменение и удаление — в будущих версиях.
- Возможность расширять функционал без переписывания базовых модулей.

### 1.2 Что не входит в 1.0

Создание/удаление/замена облачных файлов, переписывание тегов, физическое разделение FLAC по CUE, интеграции с внешними каталогами обложек или текстами, ИИ-агенты, синхронизация настроек между устройствами через отдельный сервер, поддержка нескольких пользователей/источников, социальные функции. Проектировать точки расширения можно; реализовывать функции только в отдельной задаче.

## 2. Сценарии пользователя

**UC-01 Подключение.** Пользователь вводит URL (по умолчанию Mail WebDAV), логин и пароль внешнего приложения в локальном интерфейсе. После проверки видит результат соединения и папку `/AllMusic`. Пароль не показывается в логах и не сохраняется в проекте.

**UC-02 Первое сканирование.** Приложение получает дерево папок и перечень поддерживаемых музыкальных файлов, быстро показывает доступный каталог. Теги и обложки могут обрабатываться постепенно в фоне. Ход сканирования и ошибки доступны пользователю.

**UC-03 Просмотр.** Можно переключаться между представлением по папкам и по тегам (исполнитель, альбом, композиция), искать и сортировать. Данные уже просканированной коллекции доступны без обязательного повторного обхода сети.

**UC-04 Воспроизведение.** Пользователь включает файл или альбом, выполняет паузу, перемотку, переход к следующему/предыдущему треку и управление очередью. Загрузка и декодирование не блокируют интерфейс.

**UC-05 Перебои сети.** Плеер использует уже закэшированные данные, показывает понятный статус, пытается безопасно восстановить загрузку. При недостатке данных сообщает о необходимости сети вместо зависания.

**UC-06 Офлайн.** Пользователь помечает треки/альбомы как доступные без сети, видит прогресс загрузки и объём кэша. При отсутствии интернета может слушать полностью скачанные и проверенные записи.

**UC-07 Обложки.** В списках быстро появляются закэшированные небольшие изображения. Если источник изменился, обложка в разумный срок переиндексируется без постоянной полной перезагрузки всех файлов.

**UC-08 Android.** Плеер продолжает воспроизведение при свёрнутом приложении и заблокированном экране; предоставляет системные кнопки управления и корректно реагирует на аудиофокус и гарнитуру.

## 3. Функциональные требования версии 1.0

### 3.1 Подключение и источник

- **FR-001** Подключение к WebDAV по HTTPS, логин + пароль внешнего приложения, с проверкой TLS; никаких сертификатных обходов «для удобства».
- **FR-002** Логическая изоляция всех запросов чтения в `/AllMusic` с нормализацией URL, Unicode, путей, `..`, encoded-slash и редиректов; границу нельзя расширять только за счёт пришедшего от сервера `href`.
- **FR-003** Рекурсивная инвентаризация через `PROPFIND` (предпочтительно `Depth: 1` по папкам); устойчивость к отсутствующим свойствам, ошибкам 401/403/404/429/5xx, тайм-аутам, переименованиям и обрывам соединения.
- **FR-004** Инкрементальные обновления каталога по доступным признакам `getetag`, `getlastmodified`, `getcontentlength` с планируемым повторным обходом; неподтверждённые данные помечать как устаревшие.
- **FR-005** В версии 1.0 запрещены HTTP-методы записи/изменения (`PUT`, `DELETE`, `MOVE`, `COPY`, `MKCOL`, `PROPPATCH`) к реальному облаку. Юнит/интеграционные тесты должны фиксировать отсутствие таких запросов.

### 3.2 Медиатека

- **FR-010** Локальная SQLite-база со списком файлов, метаданными, обложками, статусами актуальности и настройками пользовательских списков.
- **FR-011** Теги: title, artist, album artist, album, disc/track number, year/date, genre, duration, composer (если присутствуют), идентификаторы каталогов — без принудительного переписывания источника.
- **FR-012** Представления по папкам и по тегам, включая корректную обработку сборников, различных исполнителей и альбомов с несколькими дисками.
- **FR-013** Поиск по исполнителям, альбомам и композициям, сортировка; сведения о пустых/некорректных тегах отображать честно.
- **FR-014** Медиатека доступна после перезапуска без необходимости ждать полной синхронизации с облаком.
- **FR-015** Прогресс сканирования, отмена, повтор после ошибок, ограничения одновременных запросов, приоритет воспроизведения над массовой индексацией.

### 3.3 Воспроизведение

- **FR-020** Воспроизведение MP3, FLAC, AAC и ALAC на целевых ОС, подтверждённое тестами на эталонных аудиофайлах и контейнерах (поддержка не выводится из перечня Qt API).
- Для отдельного Android Media3 spike по Issue #26 FR-020 сужен до локальных синтетических MP3/FLAC. WAV допускается как регрессионный пример; AAC и ALAC не являются критериями этой задачи. Это уточнение не подтверждает и не требует поддержку ALAC на Android.
- **FR-021** Play, pause, resume, stop, next/previous, очередь, перемотка, громкость и отображение времени.
- **FR-022** Загрузка аудиоданных асинхронно и с контролируемым запасом буфера; пользовательские операции и UI не должны зависать от WebDAV.
- **FR-023** Предварительная подготовка следующего трека по возможности, без полного скачивания всей очереди и без перегрузки сети.
- **FR-024** Офлайн-воспроизведение полностью проверенных локальных копий; частичные файлы не выдавать за доступные офлайн.
- **FR-025** Сообщать об ошибках декодирования, неподдерживаемых форматах, некорректном файле и недоступности сервера без аварийного завершения.
- **FR-026** Gapless playback для непрерывных альбомов — желаемое качество; метод реализации и критерий включения в релиз определяются после технического прототипа. Нельзя обещать точный gapless без воспроизведения и измерения.

### 3.4 Аудиокэш

- **FR-030** Дисковый кэш с ограничением размера (отдельно по устройствам), LRU/аналогичной политикой вытеснения и защитой закреплённых офлайн-треков.
- **FR-031** Раздельные состояния: метаданные скачивания, частично скачано, загружено, проверено, доступно офлайн.
- **FR-032** Временные файлы и атомарная фиксация завершённых загрузок; защита от повреждения при сбое приложения, нехватке места и повторном запуске.
- **FR-033** Идентификатор версии удалённого файла использует доступные WebDAV-метаданные и последующую перепроверку; при сомнениях устаревшая копия не должна маскироваться как актуальная.
- **FR-034** В настройках доступна очистка обычного кэша, не затрагивающая явно закреплённые офлайн-композиции без отдельного подтверждения.

### 3.5 Обложки

- **FR-040** Извлекать обложки из метаданных и, если есть, из отдельных файлов папки; приоритеты источников определяются настройкой/отдельным решением.
- **FR-041** Создавать уменьшенные изображения с ограничением пикселей и размера файла (начальный ориентир — 256 × 256; окончательные размеры утвердить после тестов).
- **FR-042** Повторно использовать одно изображение для треков/альбомов, не дублируя идентичные бинарные данные; лениво загружать UI-изображения.
- **FR-043** Не скачивать заново обложки при неизменном источнике, применять инвалидацию после обнаружения изменений исходного файла; предусмотреть ручное обновление.
- **FR-044** Если встроенная обложка требует загрузки существенной части аудиофайла, такая операция выполняется в фоне и уступает по приоритету воспроизведению.

### 3.6 Интерфейсы

- **FR-050** Общие сценарии и модели, два QML-представления: Windows/Linux (Desktop) и Android (Mobile). Общие компоненты/темы можно переиспользовать, но мобильный UI не обязан наследоваться от экранов Desktop.
- **FR-051** Desktop: библиотека по категориям/папкам, список/сетка альбомов, поиск, очередь, текущая композиция.
- **FR-052** Android: навигация касанием, экран «Сейчас играет», компактная панель управления, медиасессия/фоновая работа, поддержка системных медиа-кнопок и аудиофокуса.
- **FR-053** Внятные состояния «сканируется», «нет сети», «ошибка входа», «буферизация», «нет обложки».

### 3.7 Настройки, безопасность, наблюдаемость

- **FR-060** Защищённое системное хранилище для учётных данных там, где поддерживается; без plaintext-секретов в настройках, GitHub, снимках и логах.
- **FR-061** Журнал ошибок без паролей, токенов, приватных URL с учётными данными и чувствительных HTTP-заголовков.
- **FR-062** Диагностическая информация: прогресс синхронизации, доля кэша, тип ошибки, версия приложения, состояние воспроизведения; экспорт логов только по действию пользователя и с очисткой секретов.
- **FR-063** Разумные сетевые ограничения: ограничение параллелизма, тайм-ауты, экспоненциальные повторы с ограничением, приоритет активного трека.
- **FR-064** Уведомление о нехватке места в кэше и корректное восстановление после внезапного завершения.

## 4. Нефункциональные требования и проверки

- **NFR-01 Управляемый UI.** Интерфейс не блокируется сетевым вводом/выводом, сканированием тегов или обработкой больших обложек; проверка на искусственных задержках/тайм-аутах.
- **NFR-02 Работоспособность без сети.** После успешной индексации UI показывает локальную библиотеку; закреплённые/полностью загруженные композиции воспроизводятся без сети.
- **NFR-03 Целостность.** Сбой/отключение во время загрузки не приводит к выдаче частичного файла за полный.
- **NFR-04 Масштабируемость.** Тестовый набор минимум на 10 000 файлов и тысячи обложек без полной загрузки всех объектов в память. Численные пороги старта/памяти устанавливаются после базовых измерений на согласованных устройствах.
- **NFR-05 Надёжность.** Обрывы, отмена, возврат сети, 401/429/5xx и нехватка места обрабатываются предсказуемо.
- **NFR-06 Платформы.** Проверки отдельных сборок Windows, Linux и Android; успешный Linux CI не является доказательством работоспособности Android.
- **NFR-07 Правовые ограничения.** Перед распространением бинарных сборок проверить условия лицензирования Qt, FFmpeg, TagLib и компонентов сборки; не считать персональное использование автоматическим освобождением от условий лицензий.

## 6. Реестр рисков / вопросы перед реализацией

1. Mail WebDAV: `Range`, `HEAD`, ETag, Last-Modified, поведение `PROPFIND`, редиректы, скорость, ограничения запросов и особенности сетевых соединений — **не проверено на реальном аккаунте**.
2. Desktop Qt Multimedia/FFmpeg: gapless, извлечение встроенных обложек из удалённых файлов, частичная загрузка, перемотка и упаковка декодеров — **исследовать**.
3. Android Media3: локальный адаптер/декодирование/seek и слышимый звук — **подтвердить на Huawei**; фон, аудиофокус, медиасессия и выгрузка процесса остаются отдельными будущими проверками.
4. Идентификация «одного альбома» при ошибочных тегах и дубликатах — **определить правила**.
5. Политики фонового сканирования, размеры кэша, параметры качества и минимальные поддерживаемые версии ОС — **утвердить после прототипа**.

## 7. Возможности после 1.0

- Загрузка файлов в облако и безопасная обработка изменений с предпросмотром.
- Физическое разделение image FLAC по CUE, а возможно и виртуальные треки без разделения.
- Ревизия тегов и обложек, поиск дубликатов, контроль размеров и качества изображений.
- Выбор обложек из внешних каталогов, локальные виртуальные замены и последующая запись в файлы только по подтверждению.
- Тексты песен, перевод и синхронизированные LRC.
- Анализ медиатеки и ИИ-помощник по текущей композиции/исполнителю.
- Удаление/изменение облачных файлов исключительно с многошаговым подтверждением и стратегией восстановления.

## 8. Управление изменениями ТЗ

Добавление или изменение важной функции: предложить влияние на архитектуру, безопасность, UX, производительность, оценку объёма работ и тестов; зафиксировать решение в `DECISIONS.md` и обновить план. Codex не вправе молча менять границы первой версии.

## 10. Актуальная политика проверки Windows — решение 29.10.2026 (D-026)

Windows 11/10 образуют **единую категорию Windows Desktop** для приёмки задач.
**Windows 11 — основная ручная тестовая ОС**, и положительный результат на ней
считается достаточным Windows-критерием обычного этапа. Windows 10 сохраняется как
целевая система совместимости (см. раздел 9), но ручное дублирование на ней всех
проверок не требуется и по умолчанию не блокирует завершение задачи. Отдельные
проверки Windows 10 назначаются при явном запросе или специфичном риске.
В отчётах всегда разделять фактическую ОС испытания, целевую совместимость и
Windows Server CI: тест на Windows 11 **не является доказательством работы
на Windows 10**. Изменение относится к приёмочной политике, не к отключению
Windows 10 из целевого списка совместимости.
