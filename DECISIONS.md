## Исследование 001-B1 — 29.10.2026

Источник: прямое разрешение владельца на локальный прототип после PR #4/#6.
Ограниченный адаптер QMediaPlayer/Qt Multimedia с FFmpeg реализуется как кандидат,
без окончательного IPlaybackEngine или сетевого источника. D-008 и D-009
сохраняют статус **ПРОВЕРИТЬ**. Существующее разрешение покрывает этот эксперимент;
новых принципиальных архитектурных решений не принимали.

ffprobe реально подтвердил MP3, FLAC 16 bit, AAC LC ADTS/M4A и ALAC 24 bit M4A
на синтетических файлах. Это подтверждение содержимого фикстур, не совместимости
Qt или вывода звука. Для Qt проверяются PCM и управление отдельно от устройства.
Результаты и ограничения: [отчёт](docs/001-B1-REPORT.md).
Частичная загрузка/Range, gapless, Android audio, окончательный выбор движка
и способ распространения публичного релиза остаются открытыми.

Результаты 001-B1: Qt 6.12.0 / FFmpeg 9.0.1 действительно декодировали пять
образцов в ненулевой PCM на Linux CI; Windows PCM и упаковка подтверждены
Desktop run 40928437106 для финальной реализации df1846a. Перенос CMake-цели
подтверждён успешным APK-аудитом run 40928437092. Проблема общего SOURCE_DIR Qt сканера устранена разделением CMake scope,
без ослабления аудита APK. Это результат эксперимента, не утверждение движка.
Слышимый звук, прочие профили, сетевые источники и Android audio НЕ ПРОВЕРЕНЫ.

## D-026 — единая политика приёмки Windows Desktop (ПРИНЯТО 29.10.2026)

Владелец уточнил D-022/D-025: **Windows 11 и Windows 10 — одна категория
Windows Desktop (11/10)** для планирования тестов. Приоритетной физической
системой ручной приёмки становится **Windows 11**; успешный тест на ней достаточен
для Windows-критерия приёмки обычного этапа. Windows 10 остаётся целевой по
совместимости, но отдельная ручная проверка **не обязательна** для каждого PR и
не блокирует приёмку при отсутствии специального риска или явного требования.
Ни один результат Windows 11 не записывать как фактический тест Windows 10.
CI Windows Server также не заменяет проверку на Windows 11.
Исторические приоритеты и расписание Windows 10 выше остаются записью старого
плана; при конфликте применяется D-026.

Ручная приёмка 001-B1: владелец подтвердил **8/8** основных сценариев со слышимым
звуком на **Windows 11**, включая пять кодеков/контейнеров и управление.
Это снимает обязательность отдельной проверки Windows 10 именно для B1;
прочие аудиопрофили и пользовательский Linux остаются неиспытанными.
