# Дорожная карта — AllMusic Player

**Редакция 0.1.** Нумерация этапов — порядок работ, не оценка сроков. Не начинать следующий этап без утверждения владельца.

| Этап | Результат | Условие перехода |
|---|---|---|
| 0. Основание | ТЗ, архитектура, инструкции Codex, репозиторий, минимум CI, правила задач/PR | Документы непротиворечивы; утверждены начальные технические решения; ни один секрет не в Git |
| 1. Технический прототип | WebDAV mock + осторожная реальная проверка, получение файлов, Range, референсное воспроизведение 4 кодеков | Есть отчёт: что работает, что нет, какие fallback и выбор аудиодвижка |
| 2. Desktop вертикальный срез | Подключение, несколько папок, простой список треков, воспроизведение, pause/seek | Вручную работает на Windows и Linux, ошибки понятны |
| 3. Медиатека и интеллектуальные кэши | SQLite, теги, альбомы/исполнители, обложки, аудио-кэш, офлайн, поиск | Проходят приемочные сценарии AT-04, AT-05, AT-06, AT-07, AT-08, AT-11 |

| 6. Дополнения | CUE, обложки из внешних источников, тексты, запись в облако, ИИ | Каждая функция — отдельное мини-ТЗ, с оценкой рисков и подтверждениями |

## Пример декомпозиции этапа 1

- `1.1` Mock WebDAV: тесты `PROPFIND Depth:1` / XML namespace / Unicode / auth errors / path traversal.
- `1.2` HTTP Range spike: `206/200`, fallback, resume, случайная перемотка.
- `1.3` Эталонные локальные MP3, FLAC, AAC, ALAC (различные контейнеры/битности).
- `1.4` Playback spike на Windows/Linux, измерения времени старта и seek.
- `1.5` Android feasibility: особенности аудиодвижка и background playback.
- `1.6` Сравнение A/B аудиоархитектуры, ADR в `DECISIONS.md`, риск-отчёт.

## Стандарт отдельной задачи Codex

**Название** → **цель для пользователя** → **контекст и ограничения** → **входит** → **не входит** → **тесты/критерии готовности** → **файлы документации для обновления** → **вопросы, требующие утверждения** → **формат отчёта и PR**.

**Definition of Done:** изменения в отдельной ветке; тесты реально выполнены (результаты, команды и платформа); ошибки/ограничения раскрыты; инструкции воспроизводимы; документы `STATUS.md`/`DECISIONS.md` актуальны; не затронуты чужие данные; PR проверен и принят владельцем.

## Внеплановые идеи

Новые функции заносить в backlog; не разрывать текущий этап. Допустима отдельная критическая задача, если она исправляет риск целостности/безопасности.
