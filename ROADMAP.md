## Пример декомпозиции этапа 1

- `1.1` Mock WebDAV: тесты `PROPFIND Depth:1` / XML namespace / Unicode / auth errors / path traversal.
- `1.2` HTTP Range spike: `206/200`, fallback, resume, случайная перемотка.
- `1.3` Эталонные локальные MP3, FLAC, AAC, ALAC (различные контейнеры/битности).
- `1.4` Playback spike на Windows/Linux, измерения времени старта и seek.
- `1.5` Android feasibility: особенности аудиодвижка и background playback.
- `1.6` Сравнение A/B аудиоархитектуры, ADR в `DECISIONS.md`, риск-отчёт.

## Стандарт отдельной задачи Codex

**Название** → **цель для пользователя** → **контекст и ограничения** → **входит** → **не входит** → **тесты/критерии готовности** → **файлы документации для обновления** → **вопросы, требующие утверждения** → **формат отчёта и PR**.

**Definition of Done:** изменения в отдельной ветке; тесты реально выполнены (результаты, команды и платформа); ошибки/ограничения раскрыты; инструкции воспроизводимы; документы `STATUS.md`/`DECISIONS.md` актуальны; не затронуты чужие данные; PR проверен и принят владельцем.

## Внеплановые идеи

Новые функции заносить в backlog; не разрывать текущий этап. Допустима отдельная критическая задача, если она исправляет риск целостности/безопасности.


## 002-D-M3 — локальная проверка Android Media3 (Issue #26)

Это отдельный spike после Qt FFmpeg Android проверки и не завершение этапа 4.
Срез ограничен встроенными синтетическими MP3/FLAC, WAV как регрессионным
образцом, управлением Play/Pause/Stop/Seek, переключением трека и отображением
ошибки. Android использует Media3/ExoPlayer и системный декодер/AudioTrack;
Desktop путь не меняется. ALAC не входит в эту проверку.

Android/Desktop CI и аудит APK подтверждают сборку и состав пакета. Этап можно
рассматривать после установки APK и проверки слышимого звука владельцем на
Huawei; до этого MP3/FLAC, seek, устройство и аудиомаршруты остаются
**НЕ ПРОВЕРЕНЫ**. Фон/MediaSession/lock screen и Bluetooth L2HC/LDAC или USB DAC
не включены в Definition of Done этого spike.

## 002-D Cloud Mail — Issue #24

Следующий вертикальный срез расширяет уже проверенный локальный Media3 путь
read-only подключением к Cloud Mail через общий C++ WebDAV/Range клиент. Android
использует custom Media3 `DataSource` и непрозрачные JNI handles; не вводит новый
Java networking stack и не меняет Desktop playback. Принимаются только MP3/FLAC,
папки остаются в `/AllMusic`, звук начинает загружаться только после явного Play.
Mock обязан подтвердить HTTP 206, запрет полной загрузки при 200, диапазоны до
64 КиБ, предел кэша 256 КиБ, seek/reopen, отмену Stop/Disconnect и отсутствие
секретов в URI/логах. Android/Desktop CI и APK package audit отделяются от
ручной проверки реального Cloud Mail на Huawei; до неё приёмка остаётся
**НЕ ПРОВЕРЕНА**.

## Актуальная политика Windows Desktop — утверждено 29.10.2026 (D-026)

Для приёмки всех следующих обычных задач Windows 11 и Windows 10 учитываются как
**одна категория Windows Desktop (11/10)**. Опорная физическая система тестирования
— **Windows 11**; её успешная ручная проверка достаточна для Windows-критерия
приёмки этапа. Отдельная ручная проверка Windows 10 не обязательна по умолчанию
и не блокирует этап; выполнять её по прямому решению владельца или при конкретном
риске совместимости. Совместимость Windows 10 остаётся целевой, но **не считается
фактически подтверждённой**, пока её отдельно не проверили.


## Итог 001-D и предложение по следующим небольшим этапам — 29.10.2026

PR #9 объединён в main (93e8cb8d7314673052f141940d2bd896188b2fac); post-merge Desktop CI успешно завершился. 001-A/C/B1/B2 и оценка 001-D закрывают исследовательский цикл, но не доказывают совместимость с настоящим WebDAV, Android audio или все потоковые форматы.

Рекомендуемый порядок до медиатеки:

1. **001-E — принята 30.10.2026; PR #11 объединён в main.** Пять синтетических форматов прошли PCM/seek/завершение на Linux и Windows CI; сетевые сценарии и WebDAV-регрессия прошли. Пользовательский Stop отменяет активный Range GET до остановки/отсоединения плеера; проверен повторный сетевой и локальный запуск. Отчёт фиксирует тайминги и память, callback gaps не выдаются за доказательство слышимости. Реального WebDAV ещё не было; физическая Windows 11 ручная приёмка 5/5 форматов и Stop/restart прошла без замечаний.
2. **Отдельная read-only проверка Cloud.Mail.ru.** Главный неизвестный для production-сетевого источника. Требует отдельного явного разрешения владельца и запуска владельцем из локальной конфигурации. Пароли, токены, музыка и чувствительные заголовки не записывать в Codex, CI или PR. В 001-D подключений не было.
3. **Android audio feasibility.** Сначала локальный вывод, затем аудиофокус/гарнитура, затем экран блокировки, media session и фон на Huawei. Сборка APK не доказывает работу аудио.
4. **Контракты и Desktop вертикальный срез.** После первых трёх результатов владелец выбирает интерфейсы и fallback; затем соединить тестовый источник и воспроизведение. Только после этого планировать индекс и постоянный кэш.

Прототип остаётся loopback-only; Android audio feasibility — отдельная работа.
